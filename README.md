# StockSentry · 智能盯盘与投研生成系统

一个本地运行的 A 股盯盘反馈应用：**实时监控关键指标 → 生成利好/利空信号 → 输出明确的入场/离场判定 → 一键生成投研报告与持仓攻略**。

> **在线体验（零安装，纯静态）**
> - WorkBuddy 托管：https://stocksentry-ashare.app.workbuddy.host/
> - GitHub Pages：https://martens-100.github.io/stock-sentry/
>
> 两个链接均为浏览器直连行情接口的静态版，打开即用。

规则引擎的大脑来自你提供的两份投研文档（《中兴投研持仓攻略》《科伦药业投研尽调报告》），系统从中抽象出「8 章报告模板 + 利好/利空双向监控清单 + 持仓策略参数」模型，并可套用到任意 A 股标的。

## 快速开始

```bash
cd stock-sentry
cp .env.example .env     # 可选：需要自定义端口/跨域白名单/密钥时才要这一步
node server.js
# 浏览器打开 http://127.0.0.1:8848
```

零第三方依赖，仅需 Node.js ≥ 18。默认端口 8848，可用 `PORT=9000 node server.js` 修改，或写进 `.env`。

常用命令：

| 命令 | 作用 |
|---|---|
| `npm start` | 启动服务端 |
| `npm run build:static` | 构建静态版到 `docs/`，**构建后自动做密钥扫描，命中即失败** |
| `npm run check:secrets` | 只做密钥扫描（源码 + 产物） |
| `npm run check` | 扫描 + 重建，提交前跑一次最稳 |

## 在线版（纯静态 / 零服务端）

项目同时提供**完全静态**的版本，可直接托管在 GitHub Pages 等任意静态空间，无需服务器、无需后端进程：

```bash
node build-static.js      # 生成 docs/ 目录（index.html + bundle.js + static-api.js + app.js + style.css）
```

静态版与原版**功能完全一致**，差异仅在数据处理位置：

| | 服务端版 | 静态版 |
|---|---|---|
| 运行方式 | `node server.js` | 打开 `docs/index.html`（或托管到 Pages） |
| 行情请求 | Node 转发 | **浏览器直连腾讯财经接口**（该接口已开放 `access-control-allow-origin: *`） |
| 自选股存储 | 服务端 `data/watchlist.json` | 浏览器 `localStorage` |
| 股票搜索 | 腾讯 smartbox（可选叠加东方财富） | 腾讯 smartbox JSONP 联想 |
| 主力资金流 | 东方财富（大单口径） | 降级为**分时主动买卖估算**（东方财富接口无 CORS） |
| 报告下载 | 写入 `out/` + 前端下载 | 纯前端 Blob 下载 |

原理：`lib/` 下的核心模块（数据层 / 指标 / 规则 / 引擎 / 报告）全部写成**同构**代码，`build-static.js` 把它们打包进 `docs/bundle.js`（挂载到 `window.SentryLib`），再由 `static-api.js` 在浏览器内实现 `/api/*` 的全部接口。

## 密钥隔离与安全基线

静态产物是**公开**的 —— 发布到 GitHub Pages 后任何人都能查看每一个字节。因此这里的思路不是"把 key 藏好"，而是**让 key 根本不存在于产物中**。

### 三层防线

| 层 | 机制 | 位置 |
|---|---|---|
| **源头** | 所有凭据只从服务端环境变量读取，源码中禁止出现字面量；未登记的密钥名会直接抛错 | `lib/config.js` |
| **构建** | `@node-only` 区块在打包成浏览器产物时被**整段剥离**；产物生成后逐字节扫描，命中即**中止构建**（退出码 1） | `build-static.js` |
| **运行时** | Host 头校验、跨域默认拒绝、分接口限流、错误脱敏、严格 CSP | `lib/guard.js` · `server.js` |

### 1. 凭据只在一个地方读

```js
const cfg = require('./lib/config');

cfg.secret('EASTMONEY_TOKEN');   // 未登记的密钥名 → 抛错，强制先登记
cfg.option('PORT', 8848);        // 普通配置可以有默认值
cfg.num('RATE_LIMIT_PER_MIN', 120);
cfg.flag('TRUST_PROXY', false);
```

新增密钥的固定流程：`.env.example` 加说明 → `lib/config.js` 的 `SECRETS` 登记 → 业务代码用 `secret()` 取。
本地配置写在 `.env`（已被 `.gitignore` 排除，且 `git check-ignore .env` 可自证），零依赖的 `.env` 加载器不会覆盖部署平台已设置的环境变量。

### 2. `@node-only`：不打包，就无从扒取

任何读取凭据、或只在服务端成立的代码，用区块标记包起来：

```js
/* @node-only */
const token = cfg.secret('EASTMONEY_TOKEN');
if (token) { /* ... 只有服务端会走这里 ... */ }
/* @end-node-only */
```

`build-static.js` 会校验标记配对并整块删除，因此浏览器产物里**连调用凭据的代码都不存在**。当前被剥离的内容包括：`https`/`zlib` 引入、Node 请求分支、东方财富资金流与搜索分支、`.env` 读取逻辑。

### 3. 构建闸门：宁可构建失败，也不发布带密钥的文件

```bash
npm run build:static      # 构建 + 自动扫描，发现有凭据 → 直接失败
npm run check:secrets     # 只扫描（源码 + docs/ 产物）
```

扫描器覆盖：GitHub / OpenAI / AWS / Google / Slack / Stripe 等密钥格式、私钥文件、URL 查询串里的凭据、硬编码赋值、`Bearer` 字面量，以及产物中出现的 `process.env`；另有长十六进制串与 JWT 的启发式告警。扫描器**也会扫描自己**（denylist 用字符串拼接定义，因此本文件不含连续密钥字面量），并带一份"已泄漏值"黑名单。

### 4. 服务端：防止接口被当作免费 API 扒

| 措施 | 默认值 | 说明 |
|---|---|---|
| Host 头校验 | 开启 | IP 字面量与 `localhost`/`*.local` 放行，其余域名需 `TRUSTED_HOSTS`。**拦截 DNS Rebinding**（网页把 evil.com 解析到 127.0.0.1 后直连本机服务） |
| 跨域 | 仅同源 | 已移除早前的 `Access-Control-Allow-Origin: *`；需要跨域时用 `ALLOWED_ORIGINS` 显式白名单 |
| 限流 | 120 次/分；分析类 30 次/分 | 按「IP + 限额档」隔离，重接口额度不会被轻接口挤占 |
| SSE 并发 | 4 / IP | 防止单机占满连接 |
| 请求体 | 32 KB | 防内存耗尽 |
| 错误响应 | 只回事件号 | 不再回显 `err.message`（可能含上游 URL、文件路径）；细节只进服务端日志 |
| 静态服务 | 路径归一化 + 前缀校验 + 拒绝点开头文件 | 目录穿越与 `.env` 读取均返回 403/404 |
| CSP | `default-src 'self'` | 另配 `nosniff` / `no-referrer` / `X-Frame-Options: DENY` / `CORP: same-origin` |

启动时会打印当前安全基线，便于确认配置是否生效：

```
  ▸ 安全基线：
      跨域        仅同源（默认拒绝跨域）
      限流        120 次/分，分析类 30 次/分，SSE 并发 4
      Host 校验   已开启
      凭据        已登记 1 项，全部未配置（当前功能无需凭据）
```

> 部署到自定义域名时记得设置 `TRUSTED_HOSTS=<你的域名>`，否则 Host 校验会返回 403。

## 功能

### 1. 实时盯盘看板
- 侧边栏自选股实时报价（默认每 8 秒自动刷新，可关闭）
- 主面板 16 项关键指标：现价/涨跌、开高低收、成交额、换手率、量比、振幅、PE(TTM)/PE(动)/PE(静)、PB、总市值、52 周位置、ATR 波动率、MA5/MA20/MA60、RSI、MACD 柱
- 分时走势图（价格线 + 均价线 + 成交量柱）
- K 线图（120 日）+ 均线 + **布林上下轨** + **回归导轨通道** + 成交量 + MACD，三组图层可独立开关

### 2. 盯盘结论（评分 + 动作）
综合评分 = 技术面 × 权重 + 策略面 × 权重（画像质量决定权重分配），输出七档动作：

| 动作 | 触发条件 |
|---|---|
| 积极入场 | 综合 ≥ 78 且不在目标位/止损位 |
| 可分批建仓 | 综合 66–77 |
| 持有观察 | 综合 52–65 |
| 观望等待 | 综合 40–51（趋势未多头） |
| 建议减仓 | 综合 40–51（趋势多头） |
| 建议离场 / 建议回避 | 综合 < 40，或跌破止损位，或跌破硬止损 |
| 分批止盈 / 不建议追高 | 触及第一/第二目标位 |

**硬性风控优先**：跌破硬止损 → 无条件离场；跌破止损位 → 止损离场；触及目标位 → 分批止盈。这三条覆盖评分结果。
**盈亏比修正**：若盈亏比 < 1，自动把「积极入场/可分批建仓」下调一级，避免低赔率交易。

### 3. 信号引擎（利好 / 利空 / 中性）

**通用技术规则（17 类）**：均线排列、价格与 MA20/MA60、MACD 金叉死叉与零轴位置、RSI 超买超卖、KDJ 金叉死叉与 J 值极值、量价配合（放量涨/放量跌/缩量涨/缩量跌）、20 日新高新低突破、52 周位置分位、主力资金净流入流出、内外盘博弈、短线急涨急跌。

**上下轨线与导轨区间规则（10 类）**：
- 布林三轨：站上/逼近上轨、跌破下轨（按导轨方向区分「超跌」与「弱势延续」）、中轨上下方
- 布林带宽状态：收口（变盘临近）/ 开口（趋势加速），基于近 120 日带宽分位
- 回归导轨通道：上升/下降/水平导轨、通道内位置、突破上轨、跌破下轨、沿上轨/下轨运行
- 唐奇安区间（20 日）：突破上沿 / 跌破下沿 / 区间内位置

**个股画像规则**：来自研报的关键价位（建仓区间/止损/目标位）触发判定、持仓成本盈亏、PE 相对合理区间、监控清单中的可自动判定项。

每条信号都带：方向、强度（1–5★）、权重、结论文字、**数据依据**（具体数值与口径）。

### 4. 轨道综合研判
把布林上下轨位置与回归导轨方向组合成可执行的区间判断，输出九类区域之一，例如：

- `上升导轨 · 回调低吸区` — 导轨向上且价格回落至通道下沿
- `上升导轨 · 上沿持有区` — 沿上轨运行，持有但不宜追加
- `下降导轨 · 下沿回避区` — 下降通道末端，趋势未反转前不抄底
- `下降导轨 · 上沿减仓区` — 反抽至上轨是减仓窗口
- `水平导轨 · 箱底承接区 / 箱顶减持区` — 箱体震荡的区间交易

配三条可视化位置条（布林轨道 / 回归导轨 / 唐奇安区间），标出当前价格在轨道中的精确位置。

> 口径：布林带 = 20 日均线 ± 2 倍标准差；回归导轨 = 最小二乘线性回归中轨 ± k 倍残差标准差，窗口与 k 值**自适应收窄**（60/45/30/20 根，k=2.0/1.8/1.6/1.5），确保通道宽度可解读；唐奇安 = 近 20 个交易日最高/最低价。

### 5. 交易计划
建仓区间、第一/第二目标位、止损位、硬止损位、盈亏比（含参考入场价与风险 ATR 倍数说明）、建议仓位上限、关键支撑/阻力位（枢轴聚类 + 均线补齐）、分批节奏（买入场景为「越跌买越多」的三档递进；卖出场景自动切换为「仓位处置节奏」）。

### 6. 投研报告与持仓攻略自动生成
点「生成报告」，按投研尽调模板输出完整报告并同时落盘 HTML + Markdown：

```
⟡ 实时盯盘面板（Live Monitor）
⟡ 上下轨线与导轨区间研判
一、执行摘要（Executive Summary）
二、财务与估值透视
三、经营与市占率拆解
四、风险控制（Risk Consulting）
五、长线投资者：筹码结构与散户拥挤度
六、团队综合研判
七、产业链与业绩兑现节奏
八、持仓攻略：策略建议与操作纪律
    ├ 当前位置与结论
    ├ 交易计划（建仓/目标/止损/盈亏比）
    ├ 分档止盈纪律
    ├ 分批建仓节奏
    ├ 关键支撑/阻力位
    ├ 核心监控清单（利好/利空双向）
    └ 实时信号明细
```

文件写入 `stock-sentry/out/`，命名为 `{代码}_{名称}_投研持仓攻略_{日期}.html/.md`。

## 添加任意股票

在左上角搜索框输入**代码、名称或拼音**（如 `600519`、`贵州茅台`、`gzmt`），点击结果即加入自选股。系统会自动：

1. 拉取该股实时行情与近 300 日 K 线
2. 计算全部技术指标与轨道区间
3. 匹配画像库 —— 有画像则套用其建仓区间/止损/目标位/监控清单；无画像则走 ATR 波动率推算的通用模板
4. 生成该股的信号、结论、交易计划与完整报告

## 目录结构

```
stock-sentry/
├── server.js              # HTTP 服务：静态托管 + REST API + SSE + 安全基线
├── lib/
│   ├── config.js          # 凭据与配置唯一入口（只读环境变量，浏览器端恒为空）

│   ├── source.js          # 多源行情层（腾讯主源 / 新浪备源 / 东财资金流），含 TTL 缓存与降级
│   ├── tech.js            # 指标引擎：MA/EMA/MACD/RSI/KDJ/BOLL/ATR/枢轴/回归导轨/唐奇安/轨道研判
│   ├── rules.js           # 信号规则引擎：通用技术规则 + 上下轨导轨规则 + 个股画像规则
│   ├── engine.js          # 分析引擎：评分模型、动作判定、交易计划、风控修正
│   └── report.js          # 报告生成器：8 章模板 + Markdown→HTML 渲染
├── scripts/
│   └── scan-secrets.js    # 密钥扫描器（源码 + 构建产物），命中即失败
├── build-static.js        # 静态版打包：剥离 @node-only 区块 → 打包 → 扫描产物
├── static-api.js          # 静态版后端替身：在浏览器内实现 /api/*
├── data/
│   ├── profiles.json      # 画像库（从中兴通讯/科伦药业研报提取的规则与策略参数）
│   └── watchlist.json     # 自选股与刷新频率
├── public/                # 前端（原生 JS + Canvas 自绘图表，无任何 CDN 依赖）
├── docs/                  # 静态版产物（GitHub Pages 直接托管此目录）
├── .env.example           # 环境变量模板（只写键名与说明，绝不写真实值）
└── out/                   # 生成的报告文件
```

## 使用画像库（把新研报喂给系统）

编辑 `data/profiles.json`，在 `profiles` 下新增条目即可让系统"学会"一只新股票：

```jsonc
"600519": {
  "code": "600519", "market": "sh", "name": "贵州茅台",
  "profileQuality": "high",           // high=策略面权重 55%；low=25%；缺省 none=纯技术面
  "thesis": "核心投资逻辑……",
  "valuation": { "peTtm": 20, "pb": 6.3, "fairPe": [18, 25], "benchmark": "白酒板块均值", "note": "……" },
  "levels": {                          // ← 交易计划与信号直接引用这些价位
    "entry": [1200, 1280], "stopLoss": 1150, "hardStop": 1100,
    "target1": 1450, "target2": 1600, "positionLimit": 0.15
  },
  "cost": 1272.75,                     // 持仓成本，填了才会输出"浮盈/浮亏"与持仓动作
  "monitors": [                        // ← 监控清单，也就是"利好/利空双向"那张表
    { "dim":"渠道动销", "metric":"飞天批价", "window":"每周",
      "bull":"批价回升至 2300 元以上", "bear":"批价跌破 2000 元",
      "weight":9, "auto":null }        // auto 可为 grossMargin/revenueGrowth/profitGrowth/segmentShare/chipConcentration/valuationPE
  ],
  "fundamentals": { "revenue2025":"……", "netProfit2025":"……" },
  "risks": ["……"], "chips": "……", "verdictNote": "……"
}
```

保存后刷新页面即生效，无需重启服务。`auto` 字段指向的监控项若能被实时数据判定，会在信号面板中自动触发，其余作为人工跟踪项保留在清单里。

## 数据来源与口径

| 数据 | 来源 | 口径 |
|---|---|---|
| 实时行情快照 | 腾讯财经 `qt.gtimg.cn` | GBK 编码，字段含 PE(TTM)/PE(动)/PE(静)/PB/量比/换手率/涨跌停价 |

| 主力资金流 | 东方财富 `push2.eastmoney.com` | 主力净流入（大单口径） |
